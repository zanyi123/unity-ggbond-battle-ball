## 二、引擎API耦合点对照表

> 这是之前迁移失败的根本原因——只翻译业务逻辑，没翻译引擎特性。
> 2026-09-07 按实况复核：大部分耦合点已落地；物理体系实际走 **3D Collider**（原方案假设 2D），球员移动为直改 transform.position 的手动方案。

| GD 引擎特性 | Unity 等价 | 状态 | 怎么做（落地方法 / 后续验证要点） |
| --- | --- | --- | --- |
| `[autoload]` 全局单例 | `RuntimeInitializeOnLoadMethod` + `DontDestroyOnLoad` | ✅ 已完成(7个) | `RuntimeAutoBootstrap.cs` 按依赖顺序统一创建；新增 Manager 在此注册一行。验证：运行时无重复实例 |
| `FileAccess.open` + `JSON.parse` | `Resources.Load<TextAsset>` + `Newtonsoft.Json` | ✅ 已完成 | `Resources.Load<TextAsset>("data/xxx")`（**路径不带 .json 后缀**）→ `JsonConvert.DeserializeObject<List<Dictionary<string,object>>>(ta.text)`；静态数据走 Resources，动态存档走 `File.ReadAllText/WriteAllText` |
| `signal x` + `.connect()` + `.emit()` | `event Action` 或 `UnityEvent` | ✅ 基本完成 | 18 个文件已用 `public event Action<T> OnXxx;`；GD `emit()` → `OnXxx?.Invoke(arg)`，`connect(cb)` → `OnXxx += cb`。**后续验证**：逐面板确认订阅/退订配对（OnEnable 订阅 / OnDisable 退订），防重复订阅与泄漏 |
| `$Node/Path` / `get_node()` | `transform.Find()` / `GetComponent<>()` | ✅ 已完成 | 本项目 UI 以纯代码创建为主，引用直接持有；动态查找用 `transform.Find("Path")?.GetComponent<T>()`，失败即 `Debug.LogError` 暴露路径错误 |
| `add_child()` / `remove_child()` | `Instantiate()` + `SetParent()` / `Destroy()` | ✅ 已完成 | 动态 UI：`Instantiate(prefab, parent)`；销毁：`Destroy(go)`；高频创建（技能图标/列表项）后续可加 `ObjectPool` 优化 |
| `queue_free()` | `Destroy(gameObject)` | ✅ 已完成 | 面板关闭统一 `Destroy(gameObject)`；批量销毁子物体必须倒序 for 循环 |
| `_ready()` | `Awake()` / `Start()` | ✅ 已完成 | 自身缓存/Instance 赋值放 Awake；依赖其它单例的初始化放 Start（Bootstrap 已保证顺序） |
| `_process(delta)` | `Update()` | ✅ 已完成 | 战斗层 13 个脚本已有 Update；`Time.deltaTime` 即 GD delta。注意 `timeScale=0` 时 Update 仍执行，暂停 UI 逻辑可利用 |
| `_physics_process(delta)` | `FixedUpdate()` | ✅ 已完成 | 移动/球物理/AI 决策已在 FixedUpdate（步长 `Time.fixedDeltaTime`=0.02s）；纪律：物理相关全进 FixedUpdate |
| `set_anchors_preset(PRESET_FULL_RECT)` | `anchorMin/Max=0/1; offset=0` | ✅ 已完成 | 公共工具方法 4 行赋值（anchorMin=zero, anchorMax=one, offsetMin/Max=zero），全屏面板统一调用 |
| `Input._input(event)` | `Input.GetKey/GetAxis` | ✅ 已完成 | `InputManager.cs`(9.7KB) 已封装；方向输入 `GetAxisRaw` 或 KeyCode 轮询。后续需手柄/重绑定时再迁新 Input System |
| `Area2D` + `body_entered` | `Collider`(3D) + `OnTriggerEnter(Collider)` | ✅ 已完成（3D 方案） | ⚠️ **实际走 3D 物理**：球挂 Collider(isTrigger)+Rigidbody，`OnTriggerEnter(Collider other)` 检测接球/伤害；PlayerController 已自动给球员补 Collider。**不要引入 2D 物理混用** |
| `CharacterBody2D.move_and_slide()` | 直改 `transform.position` | ✅ 已完成（手动方案） | ⚠️ **实际实现**：`transform.position += velocity * Time.fixedDeltaTime`（8 个文件），与 GD 手动 velocity 思路一致、避开物理推挤；击退用位移注入同通道。后续若要真实物理反弹再局部改 Rigidbody.AddForce |
| `Timer` 节点 | `Coroutine` / Update 计时 | ✅ 已完成 | 一次性延时 `StartCoroutine`；需暂停感知的计时用 Update + `timer -= Time.deltaTime`（自动随 timeScale 暂停） |
| `Tween` | 协程 `Mathf.Lerp` 插值 | ✅ 已完成（无 DOTween） | `SkillVisualManager.cs` 已用协程插值实现光环/特效；后续复杂缓动链再评估 DOTween，当前不为装而装 |
| `preload("res://...")` | `Resources.Load<T>()` | ✅ 已完成 | 数据 JSON 全在 `Assets/Resources/data/`；Prefab 动态加载放 `Resources/Prefabs/`（当前 UI 多为代码构建，需求低） |
| `StyleBoxFlat`(圆角边框) | `Image` 纯色 + Outline | ⚠️ 纯色替代（可用） | 现用纯色 Image；**升级路线**：美术出 9-Slice 圆角 PNG → `Image Type=Sliced` 一次性替换 |
| `ScrollContainer` | `ScrollRect` | ✅ 已完成 | Viewport + Content(VerticalLayoutGroup + ContentSizeFitter)；**注意 Content 必须由 Layout 自动撑高才能滚动** |
| `ProgressBar` | `Image` fillAmount / sizeDelta | ✅ 已完成 | HUD/属性条统一 `Image(Type=Filled, Fill Method=Horizontal)` 改 `fillAmount`(0~1) |

| **单例防重复**  | autoload 天然唯一                                        | Awake 里 `if(Instance!=null&&Instance!=this) Destroy(gameObject); return;`                                                                                       | ✅ **已完成**       |

### 4.1 补充：怎么做（2026-09-07 复核）

**状态复核：✅ 全部已完成**（`RuntimeAutoBootstrap.cs` 统一引导，7 个 Manager 全部注册）。

1. 在 `Assets/_Project/Scripts/` 对应目录建 `XxxManager.cs`，提供 `public static XxxManager Instance;`

3. 在 `RuntimeAutoBootstrap` 中按依赖顺序追加创建语句（依赖别人的排后面）

「查询方法」验证要点：
- `GetCharacterById(id)` 内部用 `Convert.ToInt32` / `Convert.ToSingle`（Newtonsoft 反序列化的数字默认 long/double，直接强转 int 会抛 InvalidCastException）

- 空值防御：`dict.TryGetValue(key, out var v)` 取不到时返回默认值并 `Debug.LogWarning`

## 十二、关键迁移原则

1. **先理顺引擎特性，再翻译业务逻辑**：autoload → 单例自动创建，signal → event，节点路径 → transform.Find
2. **UI 坐标统一用 pivot (0,1)**：GD position 是左上角，Unity 默认 pivot 是中心，必须统一
3. **数据源统一走 DataManager**：不要在 UI 里直接读 JSON
4. **战斗层先做最小可运行**：1球员+1球+简单AI，再逐步加功能
5. **AI 决策是纯数学**：ai\_manager 的效用评分可直接翻译，不依赖引擎

**Unity 实战新增原则（2026-09-07）**：

6. **3D 物理不混用 2D**：本项目已按 3D Collider + 手动 velocity 落地，禁止再引入 2D 物理体系
7. **真调用优先、事件兜底**：跨模块调用先直调方法（try-catch），失败再走事件回调（备战→开赛已验证此模式）
8. **骨架先行**：大文件先落「合法骨架」（编译通过 + `[TODO Step-*]` 标注），再逐步补全（BattleHud 即此模式）
9. **GD 兼容层收口在 Player**：GD 风格多态方法（AddBuff 6 参等）集中在 PlayerController，不扩散到其它脚本
10. **比例尺 0.01 铁律**：GD 像素 × 0.01 = Unity 米，所有数值换算统一走此比例（已实测球员 0.77m/球 0.30m）
